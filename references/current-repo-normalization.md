# 当前仓库规范化与目标平台收敛

用于已有项目不开发新功能，只整理当前代码、仓库、目录、目标平台和交付纪律的场景。

## 适用范围

- 补正式 PRD 和开发短计划；
- 归档“已完成摘要”，避免其继续冒充开发计划；
- 统一 Windows 正式项目目录名称；
- WSL 继续通过 `/mnt/<drive>/...` 访问同一份 Windows 文件；
- 收纳运行日志并检查 `.gitignore`；
- 修正文档中的过度承诺；
- 测试、提交和推送当前基线。

不自动实现 GitHub Issues、路线图或未来功能。

## 推荐顺序

1. **确认范围**：给出“只文档 / 推荐规范化 / 连目录一起迁移”等本质不同选项；用户选择即视为确认。
2. **先写 PRD**：记录当前功能、本轮范围、非范围、唯一源码位置、隐私边界和 AI Agent 开发边界。
3. **写短计划**：每项写准确文件、步骤、需求依据和验证；把旧“已实施”内容迁为完成记录。
4. **修改仓库**：日志等运行状态收进 `runtime/` 并整体忽略；启动器自动创建目录。
5. **确认目标平台范围**：把“代码理论可运行的平台”和“当前产品正式支持的平台”分开。若当前只做 Windows，本轮就让 README、Prompt、公开 Skill、命令示例、`platforms` 声明和注释统一为 Windows；不要保留未被当前产品承诺的其他平台教程。
6. **迁移前查引用**：项目内、Hermes 本地路由参考、快捷方式或项目配置；会话转储只作为历史，不回写。
6. **停止占用进程**：目录或日志被 Windows 进程占用时，先运行项目停止脚本并确认端口关闭，再移动文件或目录。
7. **重命名目录**：确认新目录不存在后一次性移动；Git 仓库随目录整体移动，不重建 `.git`。
8. **同步有效引用**：更新本地私有路由路径；公开 Skill 仍保持路径发现机制，不写维护者绝对路径。
9. **分级验证**：
   - 全量自动化测试；
   - BAT ASCII + CRLF 字节检查；
   - `git diff --check`；
   - `.gitignore` 命中验证与 tracked-private 检查；
   - 敏感信息扫描；
   - Windows 原生 PowerShell 从不同 cwd 启动；
   - HTTP 页面/API 200；
   - 停止后端口关闭。
10. **诚实报告 GUI 证据**：调用 `explorer.exe` 和 HTTP 成功，不等于工具肉眼确认浏览器窗口。把“调用已执行”与“可视化人工验收”分开写。
11. **提交推送**：先 `git diff --cached --check`，再提交、推送，最后比较本地 HEAD 与远端 `main`；push 不等于 Release。

## 容易踩坑

- 把 `/mnt/d/...` 当成第二份 WSL 项目，误删 Windows 唯一源码。
- 审查时把所有 open Issues 混入“当前必须修改”。
- 为目录干净直接删日志，导致 BAT 失败无法诊断；正确做法是收进 ignored runtime 目录。
- 目录正在被 Windows `cmd.exe`、Python 或 PowerShell 占用时强行移动日志或目录。
- 用静态 BAT 测试替代 Windows 原生生命周期测试。
- 在公开 PRD 中写维护者真实绝对路径；公开文档只描述环境原则，私有路由参考才保存实际路径。
- 把执行工具所在环境误写成产品支持平台。Hermes 在 WSL 执行，不代表 README 必须保留 WSL/Linux 使用说明。
- 只删 README 的平台段落，却漏改 Prompt、公开 Skill 的 `platforms`、示例命令、shebang 和代码注释。
- 移动目录后只测代码，不查本地 Hermes 路由引用。

- [ ] 唯一正式源码位置已明确
- [ ] 公开文档、Prompt、Skill 和示例命令与当前目标平台一致
- [ ] 旧平台名称、命令和挂载路径扫描为 0（历史完成记录或测试规则除外时需明确豁免）
- [ ] 有效本地引用已更新
- [ ] runtime 私有且 Git 忽略命中
- [ ] 自动化测试和 Windows 原生启停通过
- [ ] 页面/API 200，停止后端口关闭
- [ ] 敏感扫描无真实泄漏
- [ ] 本地与远端 HEAD 一致
